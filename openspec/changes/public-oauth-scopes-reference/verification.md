- `profile:read`, `profile:write`, `users:read`, `users:write`
- `locks:read`, `locks:write`, `shared_locks:read`, `shared_locks:write`

- `notifications:read`, `notifications:write`, `calendar:read`, `calendar:write`, `posts:read`, `posts:write`

`DEVELOPER_CLIENT_ALLOWED_SCOPES` contains exactly the 18 read/write values above. In `developer/services/keycloak-client-sync.service.ts`, client defaults are `basic`, `acr`, `profile`, `roles`, `web-origins`, `offline_access`; optional scopes are `address`, `microprofile-jwt` and those 18 values. Neither email nor phone is offered. The `developer` value is absent from the app allowlist.

`auth/utils/expand-scopes.ts` maps each of `locks`, `shared_locks`, `keyholder`, `messaging` to its read and write pair, with no other implication. `auth/guard/jwt-auth.guard.ts` assigns developer tokens `Object.values(AppScope)`, without `global`. `developer/repositories/developer-token.repository.ts` generates new tokens with `randomBytes(32).toString("base64url")`.

The profile response service returns the three contact fields as null when the token lacks `global`. Profile editing services reject contact changes for such tokens. The guard uses `getScopeFromContext` and `getUnauthorizedScopes`; empty handler scopes allow a valid token, while handlers without app scopes require `global`. Optional authentication still checks scopes when a token is present.
